## 一、记忆方法线：给 memory 卡的词表扩容与分体裁配方

### 1.1 调研依据

- 教学实践共识：**理解背景 → 抓意象串成画面链（意象链）→ 体会情感脉络 → 按起承转合分段 → 诵读巩固**（[知乎·古诗文背诵技巧](https://www.zhihu.com/question/19681946/answer/46218574)、[百度知道·怎样快速记住古诗词](https://zhidao.baidu.com/question/1819090020455681908.html)）。
- **串词记忆法**：抓关键词串联成链，专治长篇与无逻辑段落（[知乎·串词记忆法](https://zhuanlan.zhihu.com/p/432486838)）——这正是背诵模式「首字诀」的认知学依据。
- 与既有学术依据相容：扩张间隔（Landauer & Bjork 1978，温故桶制）+ 双重编码（画面）+ 主动回忆（遮字）已在产品闭环中落地，memory 卡是给这些机制**喂内容**的一环。

### 1.2 受控词表扩容提案（4 类 → 7 类）

现行 4 类（画面联想/结构抓手/意象锚点/名句锚点）偏"静态抓取"。调研建议补 3 类，**覆盖现行词表抓不住的三类诗**：

| 新类型 | 适用 | 一句话定义 | 示例方向 |
|---|---|---|---|
| **声韵线索** | 律诗/词/曲（韵脚规律强的） | 把"押什么韵、换几次韵、韵脚字串起来是什么"写成抓手 | 《长恨歌》韵脚随情节换部，韵变即景变 |
| **典故钩子** | 用典密的作品（李商隐/辛弃疾/赋） | 一个典故=一个预设故事，记住故事即记住句子 | 《锦瑟》五典五情绪，典与情一一对应 |
| **对比锚** | 同题/唱和/组诗 | 与库内另一首对读记忆，差异点即记忆点 | 《静夜思》×《月夜》：同月不同乡 |

规则约束（沿用现行口径）：仍 2–3 条/首、55–100 字/条、至少一处引原诗字词；**对比锚必须指向库内真实存在的 id**（写进抽检机械项：对比锚的对照篇 id 可解析，防幻觉）。

### 1.3 分体裁配方（写进 SPEC 的"按体裁优先类型"建议）

- **绝句**：结构抓手（起承转合四步）优先——绝句章法最标准；
- **律诗**：对仗对称联想并入"结构抓手"（中二联出句对句互为线索）；声韵线索次之；
- **词**：上下片结构 + 领字提示；长调注意过片处"转"；
- **曲**：口语叙事化（曲近白话，画面联想+故事化最有效）；
- **赋/楚辞**：韵段+首字诀（背诵模式已按体裁分段，memory 卡与分段器口径对齐）；
- **外国诗**：意象主线 + 复沓结构（普罗米修斯样本的"名句锚点"路线已验证可行）。

### 1.4 与产品机制的联动（memory 卡不是孤立文本）

- t=画面联想 → 背诵态**逐句意象淡入**的素材来源（双重编码）；
- t=结构抓手 → **长诗分段器**的节间说明；
- t=声韵线索 → 未来"韵脚高亮"功能的数据前提（无需新字段）；
- t=对比锚 → 详情页"同题对读"入口（P1-3 诗人页已有同题对比设计）。

## 二、翻译线：实质率门闸之外补"训诂正确性"维度

### 2.1 现有门闸防什么、不防什么

`≥90% 真改写率` 机械闸防的是"照抄凑数"，**防不了译错**。调研对照 ([信达雅](https://zh.wikipedia.org/zh-hans/%E4%BF%A1%E8%BE%BE%E9%9B%85)、[中国日报·古典诗词翻译](http://column.chinadaily.com.cn/a/202602/24/WS699d4e30a310942cc49a04a5.html)、[文言文翻译六字诀](https://zhuanlan.zhihu.com/p/105842980))，白话对译的操作规程应为：

1. **直译为主意译为辅**；补足省略主语/介词，倒装按现代语序回调；
2. **保留**人名/地名/关键意象不译；古语词替换为今语；虚词酌删；
3. **修辞还原**：互文（"秦时明月汉时关"）须展开，借代还成本体，比喻保喻体；
4. **典故句**：译文里"典故位置"给最小解释（不展开故事），详细版进串讲/story——两线口径已允许分工。

### 2.2 高频错误清单（建议作为译文抽检的新观测维度）

| 错误型 | 说明 | 抽检抓法 |
|---|---|---|
| 以今律古 | 用现代义解古义字（"走"译成走路而非跑） | 高危字表抽验（走/汤/妻/牺牲/ious 等 ~60 字） |
| 意译膨胀 | 一句译成三句、把留白填死 | 句数比 o:m ≤ 1:1.5 观测项 |
| 典故漏释 | 典故句直译字面，读者不知所云 | 用典诗清单抽验（与 #61 校勘联动） |
| 诗眼译平 | 全句通顺但诗眼字（绿/闹/空）无表现 | 名句抽验对照鉴赏辞典译文 |
| o-m 错位 | 译文对错句（合并脚本已有 o 漂移闸，语义错位仍可能） | 长诗逐句抽查 |

### 2.3 "雅"的上限参照

许渊冲"三美论"（意美/音美/形美）是译诗上限，**白话对译不追求音美形美**（那是韵文体的任务），只取"意美"——译文自身读起来要有画面。参照系统一为《唐诗鉴赏辞典》与中华书局/上海古籍译注本的译文风格（补省略但不啰嗦、有文气但不文绉绉）。

## 三、串讲线：收官复盘 + 深度观测维度（不加字段）

串讲 935/935 收官，机械门闸完备。调研对照赏析方法论（[诗歌赏析三步走：意象→手法→情感主题](https://www.thinka.ai/zh-CN/Cambridge-International-A-Level/中国语文及文学9868/诗歌赏析)、[古诗词赏析](https://baike.baidu.com/item/古诗词赏析/3175946)），建议给二轮抽检加四个**深度观测项**（只观测不判死，先跑基线）：

1. **四层完备度**：意象（看见什么）→ 手法（怎么写）→ 情感（什么心情）→ 主旨（为何而写），四层在 2–3 段里是否都有落点；
2. **诗眼是否点出**：全诗最见笔力的一字/一句，串讲有没有点（现行 N8 已抓"着一字而尽在其中"类套语——点诗眼与套套话是两回事，前者是内容要求）；
3. **体裁贴合**：起承转合框架强加给词/曲是否生硬（词应按过片转折、曲应按口语叙事评价）；
4. **与译文一致性**：跨线篇"串讲训诂 ↔ 译文训诂"是否冲突（SPEC 第 7 条已提示风险，建议 batch 复检时实际抽）。

**克制结论**：不建议新增字段（诗眼/赏析分层都装进现有 250–480 字串讲即可），符合小而美定位。

## 四、动画线：从 9 类静态图 → 每类一个"意象动词"

### 4.1 现状与差距

9 类里只有 moon/rain/spring(plantBloom) + 通用 sway/drift 有真动效；mountain/autumn/love/hope/festival/distant 是静态图复用。`anim_map.json` 带 why 字段是好底子。reduced-motion 降级已有 7 处。

### 4.2 设计原则（小而美四条，写进 anim 线规格）

1. **语义**：每个动效 = 一个意象动词（月浮/雨落/花开/枝摇/云移）——动效即记忆钩子，服务双重编码，不做装饰性动画；
2. **克制**：opacity ≤0.15 背景层 + reduced-motion 全降级（现状保持）；单文件零外部资源（inline SVG + CSS transform/opacity only，禁 JS 逐帧/禁 canvas 大面积）；
3. **一致性**：米白单线 + 界环 + 朱印的既有视觉语言（延续游戏图标体系），新增母题同构；
4. **演进依据**：新类必须先跑**全库意象统计**（意象字白名单 ∩ lines 全文频次）拿数据再定，不拍脑袋。

### 4.3 扩类提案（先统计后定，建议 9 → 最多 14 类封顶）

候选（按库内大概率高频度预判，**须实测排序后取前 5**）：snow 雪、wine 酒/杯、boat 舟/帆、wildgoose 雁、wind 风、night 夜/烛、desert 塞/沙。每类 = 1 个 CSS keyframes + 1 个单线 SVG 母题，工作量约半天/类。参考视觉语法：《长安三万里》"诗入画境"的意象转译手法（[幕后概念设计](https://www.xrender.com/v23/news/765)、[48 首唐诗视觉呈现](https://zhuanlan.zhihu.com/p/657503287)）——一个意象一个完整隐喻场景，而非拼贴；水墨扩散用 CSS filter/blur + SVG mask 可达（[水墨风 loading 实例](https://blog.csdn.net/weixin_35757531/article/details/157265647)），但注意移动端 GPU 成本，建议只在详情页英雄区用。

### 4.4 映射质量

- 一诗多意象时取**主意象**：标题字 > 名句意象 > 全文频次（`anim_map.json` 的 why 字段已记录理由，补一条"次级意象"备选即可，不加字段）；
- **背诵态联动**（round5 已设计）：揭示逐句时对应意象淡入——若该句有强意象而全诗 anim 不含该类，记录到 anim_map 的 why 里作扩类数据。
