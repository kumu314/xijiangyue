# 记忆拓展方案：从 935 到 7523（2026-11-21，zcode 起草待拍板）

> 缘起：枯木 2026-11-21 指令"诗库有七千首诗词了，记忆该拓展了"。
> 本文 = 双端记忆能力盘点 + 缺口定级 + 三阶段施工方案 + 拍板点。**未动任何产品代码**（小程序 UI 冻结至 1.0.2 过审，#311）。

## 一、双端记忆能力矩阵（实测）

| 能力 | Web（935 首，index.html） | 小程序（7523 首，shiyun-miniprogram） |
|---|---|---|
| 打卡层：读/观/知/记/温 + 五清植物 + 热力图 + 双连击 | ✅ | ✅（round7 移植，温不进满勤/learned 口径与拍板②一致） |
| **温故桶制队列**（1/3/7/14/30 + due + 回炉） | ✅ review v1（xjy_review） | ❌ **假队列**：`poemsCloud.all(3)` = `arr.slice(0,3)`——"今日任务"永远是索引前 3 首，"到期旧诗"无任何到期判定（poemsCloud.js 全文无 bucket/due） |
| **每日选题** | 今日一诗按日轮换 | ❌ 无进度指针、无轮换——7523 首等于没有学习路径 |
| **背诵模式**（遮字四级/首字诀/分段/通背入队） | ✅ | ❌ 零实现（detail 页 0 处遮字/mask/首字） |
| TTS 朗读（音色优选+破音字表） | ✅ | ❌（WebAudio 不可用，需 wx 音频方案另立） |
| 意象场景淡入（双重编码） | ✅ 9 类 | 部分：anim 仅 1233/7523（规则法补全被灵玉打回回滚，词牌污染根因已修待拍板）；viz 渐变 4/10 不达 AA（#318） |
| 记忆卡内容 | 888/935 真卡 | 935 真卡 + **6588 首空**（fallback `memory: []`；串讲 batch4/5 放量中，memory 卡未排批） |
| 语料接入 | 单文件内嵌 935 | ✅ 云 collection poems 7523 + 索引分片（poemsCloud） |

**结论：小程序端记忆功能的"打卡壳"已经齐了，但记忆的发动机——选题、温故调度、背诵体验——三件都没上。** 7523 首的量是云端的量，不是体验的量。

## 二、缺口定级（按对"记忆"的伤害排序）

- **G1 假进度（最高优先）**：每日任务 = 索引前 3 首。用户每天看到的"新学"是同一批诗，学过的永远没有第二眼——7523 首的库在这个体验下等于 3 首。**这比移植任何高级功能都基础。**
- **G2 温故无调度**：温是五项打卡之一，却没有桶制到期判定——"温习到期旧诗"字样存在，逻辑不存在。
- **G3 背诵体验缺位**：遮字四级/首字诀/通背入队是小而美定位的核心记忆体验，目前 web-only。
- **G4 记忆卡内容缺口**：6588 首空卡。内容线已有串讲 batch 放量管线（batch4/5 在跑），memory 卡可复用同一管线跟跑，不必另起炉灶。

## 三、三阶段施工方案

### 阶段一：学习指针 + 温故桶制移植（小程序纯逻辑层）——建议立即开工
- **改动面**：`utils/` 新增 review 模块（shiyun_review storage，结构与 web review v1 完全同构：`{bucket,due,last}`，桶 1/3/7/14/30、lines≥8 长诗升桶更慢、本地日禁 toISOString）；learn/detail 改"今日任务"来源：读/观/知跟**进度指针**（顺序推进 + 完成即前移），记 = 指针诗，温 = **到期队列 top1**（无到期则"今日无债，可自由翻背"——web 同文案）。
- **窗口合规**：纯逻辑 + 学习页文案微调，走**分支 + PR 不合入**，1.0.2 过审后由小羽合入（与 #311 门禁零冲突）。
- **验收门**：到期判定单测（升桶/降桶/超期回炉/本地日切日）；双端口径一致性断言（对照 index.html 温故实现逐条）；假进度回归测试（当日任务不得重复出现同一首）。
- **量级**：1 天（zcode 或小羽均可，逻辑层零 UI 风险）。

### 阶段二：背诵模式移植（1.0.2 过审后）
- 遮字四级/首字诀/通背入队移植到 detail 页；**前置**：①1.0.2 过审（#311）；②与极简轮 detail 组织化（P1-1 小程序对应物，§七已注明"另立小样"）协同设计，避免两次动同一页面；③anim 规则法重做拍板（意象淡入的内容前提，#315）。
- 温故队列状态**上云**（后端 /api/progress 扩展 review 字段，Turso 已持久）→ 双端复习进度一致，换手机不掉进度。
- 量级：2–3 天 + 小样一轮。

### 阶段三：内容跟跑（不设完成期限）
- memory 卡按串讲 batch 管线放量（SPEC memory_new 规格直接复用：受控词表 + n=12 反模板），与串讲 batch4/5 同节奏跟跑；优先给"诗入门 40 首"等路径诗配真卡（用户最先走到的地方先变好——小而美）。
- **可选大件（另拍板）**：web 端 7523 化（分片懒加载复用 part1..7 包）。web 是桌面端作品集门面，7523 化收益与成本都需要单独立项评估。

## 四、拍板点（枯木，回个序号即可）

1. **阶段一是否开工**（小程序纯逻辑分支+PR 不合入，等 1.0.2 窗口）——建议：是。
2. **每日选题策略**：进度指针顺序推进（推荐，与"诗入门 40 首"路径天然契合）／按 level 分级（先精读后拓展）／随机。建议：指针为主、随机兜底防枯燥。
3. **温故状态何时上云**：阶段一本地先行（推荐）/ 阶段二一起上云。
4. **web 7523 化是否立项**：本期不动（推荐，专注小程序记忆闭环）/ 另立专项。

## 五、不做清单

- 不逐首精校 6588 首（止血令既定：边际效用已实证为低）；
- 不在小程序 1.0.2 过审前合入任何 UI 改动（#311 门禁）；
- 不动 anim 规则法（等拍板，词牌根因已修）；
- 不新增数据字段（review 结构与 web 同构，memory 卡走既有规格）；
- 双端温故口径不再分叉（温不进满勤/learned 已双端一致，保持）。
