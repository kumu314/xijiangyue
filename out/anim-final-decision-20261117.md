## 1. 根因：为什么这件事永远完不了

不是词典不够精巧，不是门闸不够严谨，是**问题被定义错了**。四条结构性原因：

### 1.1 契约与数据错配（主因）

我们在要求对 7523 首古典诗词做 **9 类主观「意境」分类**，并接受 `HIGH ≥ 85% / MID ≥ 75%` 的字面一致率门闸。
但「意境」是主观语义判断，人类标注者亦不一致 —— 证据是金标准自己一遍遍被查出污染：

- `review-anim-backfill-313.md`：西江月 7/7 全 moon；
- #322 §1.2 又坐实减字木兰花 5/5 spring、卜算子 3/3 moon，B 类疑似水调歌头/菩萨蛮/浣溪沙；
- 自建 100 首金标准里 2 首 moon→distant 错标靠 Policy X 才洗掉。

85% 这把尺是为**机械赋值一致性**设计的（用来抓「词牌字面触发」），却拿来量**语义正确率**。
⇒ **在这个定义下，门闸不可能被诚实通过**；每一轮「修复」只是把错误搬到下一个切片：词牌污染 → hope 兜底桶 → quiet 泄漏 → 金标准污染 → 循环论证 → 「晚发」低频词误伤 → 词类 0 覆盖 → 检出力为 0 的空跑绿灯。序列没有终点。

### 1.2 字段不承重（次因，但决定 cost/benefit）

前端只有 3 行用它，且 `VIZ_CAP.quiet` 已经兜底。6290 首空 anim **现在就正常渲染**。
⇒ 全库覆盖的用户可见收益 = 0；成本 = 无限的分类/评审/文档循环。我们几周来在优化一个**用户根本不需要存在的字段**。
#79 刚修好的 9 色 viz 是唯一真实的视觉资产，而它只需要一个 class 名，不需要「7523 首都被正确分类」。

### 1.3 没有单一不变量，也没有单一属主

35 个过程文件里，每轮新增一套词典 / 准则 / 留出集 / 去泄漏词表 / 候选 json / 报告。
`anim_hope_policy.py` 有 v1 备份 + v2，`anim_write_candidate_strict.json` 832 首、`anim_ci_strip_candidates.json` 947 首、`anim_attack30.json` 3558 首同时挂「待裁定」。
⇒ 数据边界没有一处 lint，任何一轮产物都可能被下一轮误引为「已通过」（#322 §四之二 明确点名 `census_strict_report.md` 的「0 预警」空跑绿灯风险）。漂移是必然，不是意外。

### 1.4 灵玉 #322 是「框内最优解」，正因太严谨而把循环固化了

本轮首次通读全文，必须说公道话：这份裁定质量极高 —— 把精度分母与覆盖率分母切开（§2.1）、词类设为独立必测层且 `blocked` 不得开 #315（§2.2）、换批硬排除旧 220 且 seed 抽完即冻结（§2.3）、两把普查尺分开报不许事后混用（§3.3）、§五 三件套齐备。

但它**全部工作在「anim 必须是全库高精度分类字段」这个未经审视的前提内**。它自己把结局写在了 §四之二：

- 「**维持现状是合法选项**」（L163）—— 却仍把「anim 重做线继续停滞」记为代价；
- B1–B4 四条备选（全量重跑 / 宽松档 / 只放行诗类 / 停用正式普查）**全部需要 §9 改判据**，且裁定书自己逐条标注「本裁定不推荐 / 默认不放行 / 当前不可」。

⇒ 也就是说，**在这个框架里只有两个结局：继续跑到永远，或者挂起。没有「结束」。**
「一劳永逸」不可能靠把门闸钉得更准得到 —— 必须撤掉那个前提。

## 2. 决策：三条一次性动作，不是第 36 轮补丁

### 动作 ① · 把 anim 重新定义为「装饰性、可选、非真值」字段 —— **空值即终态**

写死唯一不变量（这本来就是前端现有行为，我们只是承认它）：

```
anim ∈ {"", moon, mountain, spring, autumn, love, hope, festival, distant, rain}
""  → 渲染为 quiet，是合法终态，不是 TODO，不计入「缺失」，不触发任何补全任务
```

**直接后果**：85% 门闸、220 金标准清洗、R1 换批重测、五体裁层独立必测、none 段误填率、词牌普查换尺 —— 全部**瞬间失去对象**。不是「通过」了，是这些问题不再被提出。6290 首空值从「未完成」改判为「已完成」。

### 动作 ② · 永久封死「全库批量分类」这条路（二选一，需枯木拍板）

| | **A · 冻结 + 策展（推荐）** | **B · 去数据化（真·根除）** |
|---|---|---|
| 做法 | 1233 首既有策展值定为**冻结权威集**，永不回填 6290；今后新增动画值只能经**人工编辑策展**（一个 allowlist 文件 + 一次评审），禁止任何批量 LLM / 规则分类产物写入 anim | 把 `anim` 从数据模型删除；渲染时由已有结构化字段（category / level / 季节标签）用**纯函数**派生 viz class，或恒为 quiet |
| 动产品文件 | **否**（docs-only 当天可结） | **是**：改 `detail.js` / `detail.wxml`、清理或忽略 `poems_new.json` 的 anim 键 |
| 对 #79 配色 | 保留，1233 首继续有 9 色 viz | 需重新决定 9 色 viz 去留（派生函数可保留，但不再是数据字段） |
| 832 / 947 候选 | **作废归档**，不送 #315 | 随字段一并作废 |
| 残留风险 | 仍存在「将来有人想补全 6290」的诱因，靠 ③ 的 lint + ADR 挡住 | 问题类别本身消失，无残留诱因 |
| 权限 | 枯木一句话即可 | 超出当前 docs-only 红线，需明确授权 |
| 回滚 | 弃用 ADR 即可，零数据副作用 | 需回滚前端 + 数据 |

**C · 全量 quiet**：不推荐 —— 等于把 #79 刚修的配色工作白做，收益低于 A。

**推荐 A 先一次性结案，B 留作将来真要精简数据模型时再做。** 理由：A 今天就能关掉所有 anim 卡、不动任何产品文件、零回滚成本；而「会不会再回来」由动作 ③ 保证，不靠人的自觉。

### 动作 ③ · 收摊：一份 ADR、一个 lint、关卡、归档

1. **本文**取代 35 个过程文件，成为该主题唯一活文档；
2. **一个边界 lint**（规格见 §3），任何写 anim 的补丁必须先过它，才能进入写库路径；
3. **关卡**：`#313`（打回复核）、`#315`（写库门禁）、`#322`（重测前置）三条 anim 线一并关闭，理由 = 动作 ① 使判据失去对象；`#321` 外国诗线与 UI / #79 线**独立，不动**；`#318` 若属 anim 线一并关，否则不碰；
4. **归档**：35 个过程文件移入 `out/_archive/anim-2026/`，不再作为进行中材料；`poems_new.json.bak-20261105-0230-pre-anim` 快照保留但标注「anim 线已终结」。

## 3. 单一不变量 + lint 规格（动作 ③ 的落地形态）

**A 分支（`anim_lint.py`，写库前必跑，退出码非 0 即拒）**

```
L1 值域     每条 anim ∈ 10 值集合（9 值 + ""）；否则 FAIL
L2 空值合法 "" 视为终态，不报缺失、不生成补全清单
L3 来源     写 anim 的补丁必须带 source: editorial_curated 且附人工评审过的 allowlist 文件；
            source 为 llm_batch / rule_batch / 缺失 → FAIL
            （直接封死 anim_write_candidate_strict.json / anim_ci_strip_candidates.json
              / anim_pred_full.json.ckpt 这类批量产物进入写库路径）
L4 幂等     不得覆盖已有非空 anim，除非 id ∈ allowlist 且带 override_reason
L5 禁全库   单次补丁 id 数 > 200 且非一次性策展导入 → FAIL（防止有人再跑全量 7523）
L6 冻结集   补丁目标 id ∩ frozen_1233 之外的新增，必须在 allowlist 内；否则 FAIL
```

**B 分支（同一 lint 的替代规则）**

```
L1' 字段禁止  poems_new.json 任一记录不得含 anim 键（或含也只读不用）
L2' 渲染派生  detail.js 的 viz class 由纯函数 vizOf(poem) 计算，源码内零 poem.anim 引用
L3' 无分类器 out/ 下不得存在任何对全库做 anim 判定的脚本/产物
```

lint 只做边界守卫，**不做语义判定、不重新引入金标准、不设任何百分比阈值** —— 这是它与 `anim_census.py` / `anim_gate_eval.py` 的本质区别。
