## 二、调研：现有资源与可复用方法

### 2.1 古典诗词 NLP / 标注资源
- **CCPoetry-49K**（北航，CCL25-Eval Task 5）：49,404 条指令对，含**情感推断子任务**——证明「给诗判情感/意象类别」是可评测、可对齐的任务，且有公开基准可借力。
- **NLPdzy**：朴素贝叶斯 + jieba + SnowNLP 的**多标签情感**方案——适合做「多意象共存」的 baseline，但精度有限，需 LLM 兜底。
- **chinese-poetry 开源库**：带情感标签接口，可作冷启动词典，但标签粒度粗、须清洗。
- **高质量数据集构建共识**：交叉验证 + 人工清洗是标配；直接拿模型输出当标签会自污染（正是 R2 的坑）。

### 2.2 LLM 文本分类最佳实践（本轮调研结论）
| 技法 | 增益 | 本项目怎么用 |
|------|------|--------------|
| **Few-shot（2–4 例最佳，超出 plateau）** | 显著 | 必须含**反例**：「西江月《夜行黄沙道中》→ 不是 moon，是 quiet/autumn」 |
| **Chain-of-Thought（推理链）** | +10–30% | 强制输出 `reason`：「先剥离词牌名，再看正文是否在咏月…」 |
| **Self-Consistency（多数投票）** | +10–20% | 同诗跑 3 次取多数，降低随机错判 |
| **结构化 JSON 输出** | 稳定性 | `{anim, confidence, reason}`，便于机器核验 |
| **明确类别列表** | 防漂移 | 显式给 9 值 + quiet，禁止自由发挥 |
| **heldout 50+ 真实样本** | 验收 | 220 抽样须与训练/初判**不同批次** |
| **置信度评分 + 门控** | 防过度补值 | confidence < 0.7 → 强制 quiet（治 R3） |
| **角色提示慎用**（Kim 2024） | 可能降级 | 别用「你是诗词专家」persona 包装，直接给任务 + 规则更有效 |

## 四、方案 A 的执行红线（不可打折）

1. **洗金标准**：从既有 1233 首里随机抽 ≥100 首人工复判，建立「干净金标准」；旧 anim 一律视为待验证，不默认正确。
2. **扩黑名单**：310 个词牌全量进黑名单 + 12 个乐府类别前缀（`步虚词・` 等 genre 前缀形式）；**标题先剥离词牌名/前缀再做关键字分析**。
3. **词牌命中率普查（出厂必跑）**：全库扫完，统计每个词牌被赋予各 anim 的比例；**任一词牌某 anim 命中率 >80% 即红色预警**→ 该批打回人工/quiet。这是 cheapest 的污染探测器。
4. **全库扫描交叉自检**：anim 取值分布 vs 标题关键字共现矩阵，找异常高共现（如「月」字标题却非 moon）。
5. **R1 换批重测**：220 抽样必须另取**未参与初判**的批次，门闸 HIGH ≥85% / MID ≥75%。
6. **过度补值门控**：本该留空（quiet）的比例须可解释；confidence<0.7 强制 quiet；留空率异常低（如 <5%）即预警过度补值。
7. **普查不过不交**：以上任一闸门不过，整包不写库。

## 五、提示词骨架（方案 A 用，待落地时细化）

```
你是一个诗词意象分类器。类别仅限：
{moon, mountain, spring, autumn, love, hope, festival, distant, rain, quiet}
规则：
1. 先剥离标题中的词牌名（如「西江月」「步虚词」）与乐府前缀，再分析正文意象。
2. 单字「月/秋/春/雨/山」不能单独定类——须看全诗语义。
3. 不确定或无明显意象 → quiet（宁可留空，不要硬填）。
4. 输出 JSON：{"anim":..., "confidence":0-1, "reason":...}
反例（务必遵守）：
- 《西江月·夜行黄沙道中》→ quiet/autumn，不是 moon
- 《七月》《正月》《十月之交》→ 不是 moon（是月份/农事诗）
- 《酒泉子》→ 不是 mountain（酒泉是地名）
- 《思齐》《思文》→ 不是 love
正例：
- 《静夜思》《水调歌头·明月几时有》→ moon
- 《山居秋暝》→ mountain
- 《相思》（红豆生南国）→ spring
对每首诗先写 reason 再给 anim；confidence<0.7 直接给 quiet。
```
