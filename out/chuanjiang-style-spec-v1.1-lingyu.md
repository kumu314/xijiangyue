## 一、裁定 A：「」引用分三类，不搞一律豁免、也不搞一律字面命中

### A.1 判据（可机械执行）

对串讲中每一处 `「...」` 引号内容 q，先分类，再判定：

| 类 | 定义 | 判据 | 命中失败时 |
|---|---|---|---|
| **①原诗句直引** | q 指向本诗原文的句子/词组（去标点后能在全诗 `lines[].o` 拼接串中逐字找到，或**声称**是原诗直引） | 去标点后须在全诗拼接串中逐字命中（与 zcode 工具链 `norm()` 口径一致）；单行命中作 INFO，跨行命中不算错 | **硬 FAIL**：这是防编造原诗引文的底线，绝不豁免 |
| **②非原诗单句直引** | q 不是本诗原文单句的逐字直引——含评语/诗史定位（「万古送别之祖」）/有出处典故（孔子「乐而不淫，哀而不伤」）/元引用（「悼」谈字本身）/重章缩写（「殷其雷，在南山之阳／侧／下」用／连接三章变字） | 豁免字面命中；但须**显式登记**（id + 引文 + 性质 + 主语/出处或理由），由准入层白名单承载，不提供静默豁免 | 登记缺失 → FAIL（防"什么都往评语类塞"）；登记齐全 → PASS |

**判据总公式**：`引用 PASS ⟺ ①类全部逐字命中 ∧ ②类全部已显式登记`。

**关键**：①与②的边界不是"引号里写的是不是评语"，而是**"它是否声称是本诗原文的逐字直引"**。凡声称直引却对不上原文 = 编造，硬 FAIL；凡不声称直引（评语/典故/概括/缩写）= 可登记豁免。这条边界让"编造者无法靠登记脱身"——他若把编造的诗句登记为②类，必须说出主语/出处，而编造句没有出处，登记字段填不出。

### A.2 为什么选这个方案（选 A 不选 B 的理由）

- **选"分类处置"不选"一律字面命中"**：v1 第 54 行亲口把「万古送别之祖」列为合规收束示例，第 61/64 行 pilot30 的「乐而不淫，哀而不伤」「万古送别之祖」正是照此写的。若一律字面命中，等于推翻 v1 自己给的样板、判合规文本为 FAIL——这是判据自相矛盾，不是文本有错。分类处置保住 v1 意图（防编造）同时承认评语类合法。
- **选"显式登记白名单"不选"自动识别评语"**：#344 §四 4 处逐处人工定性才分清性质，机器无法可靠自动判断"这是评语还是编造诗句"（如「万古送别之祖」无主语，靠的是"这是已知成语"的背景知识）。让机器自动放行 = 开一个编造引文的口子；显式登记把判断留在人侧、留痕可审。zcode 在 #349 报告 §四末句独立提出同一建议，两方交叉印证。
- **选"②类含重章缩写/单字概括"不选"③类硬不豁免"**（v1.1.1 修订）：初稿曾想让「殷其雷，在南山之阳／侧／下」「悼」两处改写达标。但①这两处是 #344 已逐处核过、判"非错引/非编造"的历史合法文本，②它们已在云端（枯木已据 150 首清单导入），强制改写要写真值源 + 重导，越本卡只读边界且成本高，③#348 卡面明确要求"150 首回归应复现 PASS"，硬不豁免会与卡面冲突。据实测把边界改为"是否声称原诗直引"——这两处不声称逐字直引（／是缩写、「悼」是谈字），登记即可；真正编造的诗句仍被①类硬拦。

### A.3 被否决方案与否决理由

| 被否决方案 | 否决理由 |
|---|---|
| 一律字面命中、4 处判 FAIL | 推翻 v1 第 54 行自己的合规示例；4 处均非编造原诗引文（#344 §四逐处核过），判 FAIL 是判据错不是文本错 |
| 一律豁免所有「」引用 | 直接废掉 v1 第 53 行"防编造原诗引文"的硬纪律，把最重要的校验变成空断言 |
| ②类也强制逐字命中、要求全改写 | 有出处的典故/评语本就不是诗原文，无处可"逐字命中"；强改会逼出「孔子说乐而不淫」（去引号）等别扭文本，损失信息 |
| 把非直引类一律判 FAIL 硬要改写（初稿③类方案） | 与 #344 PASS 裁决和已导入云端的历史态冲突；强制改写需写真值源+重导，越本卡只读边界；#348 卡面要求 150 首回归 PASS，此方案实测 FAIL 2 处 |

### A.4 失效边界（什么情况下本裁定不成立）

1. **②类若无法给出主语、出处或性质理由**——「万古送别之祖」能登记，是因为它是公认的《诗经》评语；「殷其雷…／侧／下」能登记，是因为其性质可写明"重章三章变字缩写，非逐字连续引用"。若某人写一句编造的"诗句"加引号，既指不出主语出处、也说不圆性质，则不得登记为②类，须退回①类按字面命中判（命中不了即 FAIL）。**"能说出主语/出处/性质"是②类豁免的必要条件；登记字段填不出 = 编造，这是防钻空子的核心闸门。**
2. **白名单登记若变成批量默认**——一旦出现"整批 30 首都把未命中引用登记成②类"的登记方式，说明登记失去逐处审核意义，本裁定失效，应回到一律字面命中并重审文本。
3. **工具链口径漂移**——②类豁免只适用于"准入层白名单"这一层；若未来 verify 工具链把白名单内置进 lib 变成默认放行，本裁定失效（等于静默豁免），必须回退到显式登记。

## 二、裁定 B：试点 3 首固化为历史豁免，后续批次一律严格 90–150

### B.1 判据

- **历史豁免名单（封闭集合，仅此 3 个 id）**：`cp_3b10971e5c`(81)、`cp_5f68aeb8dc`(83)、`cp_8ea8fd1f0c`(84)。这 3 首低于 90 字的状态**固化**，不判 FAIL、不要求补写。
- **后续所有批次（含第六批及以后）**：字数一律 `len()` 含标点 **90–150**，硬失败，无豁免。历史豁免名单**不得新增成员**。
- 字数口径：**含标点 `len()`**（规格第 23 行"逐首 len()"、#344 §三"正口径"）。去标点口径是另一项目的 SPEC，不适用本线，弃用。

### B.2 为什么选这个方案（选 A 不选 B 的理由）

- **选"固化 3 首 + 后续严格"不选"全部补写到 90"**：这 3 首是规格第 7/78 行明文"保留、不重写"、#344 §三已裁决的历史状态，且已交付 Upsert 清单、枯木已据此导入。为 3 首字数的观感一致性去写真值源、重跑五项判据、重导云端，成本远高于收益——规格第 82 行自己都写"收益有限"。固化它们、把严格口径用在后续批次，是"不为历史欠账反复付费"的选择。
- **选"封闭名单不新增"不选"每批都可申请豁免"**：可新增的豁免 = 会膨胀的豁免；严格 90–150 要成为后续批次的硬纪律，就不能留"写不够就申请豁免"的口子。3 首批是历史一次性快照，不是可复用的逃生舱。

### B.3 被否决方案与否决理由

| 被否决方案 | 否决理由 |
|---|---|
| 补写 3 首到 90 下限 | 动已交付数据、需枯木批写真值源 + 重导；规格第 82 行自评收益有限，且另外 147 首无需动 |
| 全线下限放宽到 80 字 | 为 3 首历史欠账拉低 7523 首全库基线，代价远大于收益 |
| 每批允许按"收益有限"申请豁免 | 豁免可膨胀，严格口径失去意义；3 首批是封闭快照不是制度 |

### B.4 失效边界（什么情况下本裁定不成立）

1. **枯木明确要求严格 90 下限**——规格第 82 行保留了"若枯木要求严格对齐，可对 6 首最短各补一句"的选项。若枯木拍板补写，本裁定 B 的 3 首豁免作废，名单清空，3 首按常规严格判。**这是唯一能推翻 B 的授权来源。**
2. **这 3 首因其他原因被重写正文**（如错字订正、内容修订）——重写即失去"历史交付态"身份，应顺势对齐 90–150，退出豁免名单。
3. **名单被挪用到其他线**——本豁免只针对 `cp_` 这 3 个 id 的当前串讲文本，不得作为"试点批整体豁免"或推广到其他批次。
