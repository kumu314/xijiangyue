# 云包链路核验：小程序到底读云库还是 chunks/ · 2026-11-21

> 枯木 11-21 拍板「继续之前先确认」。本笔在**继续放量前**把悬了两批的链路问题查死。结论基于小程序源码实证，非推测。

## 一、结论先行

**小程序读云数据库，不读 chunks/。** 三批串讲 Upsert 到 `poems` 集合后，前端能显示新串讲；**不需要另传 chunks 分片**。此前操作卡里"若走 chunks 需另传"的顾虑可以划掉。

但有**两个配套动作**必须做，否则会在真机验证时误判：

1. **Upsert 必须按 `_id` 覆盖**，三批清单的 `_id == id` 已核（90/90），可直接导。
2. **本地单首缓存 `poem_<id>` 不会自动失效**——这是真机验证的最大干扰源，详见第四节。

## 二、源码证据（小程序本体 `D:/WorkBuddyData/WorkBuddy/2026-07-25-14-20-30/shiyun-miniprogram`）

核心数据访问层 `utils/poemsCloud.js`（文件头注释第 1–22 行即写明架构）：

| 环节 | 代码位置 | 读什么 |
|---|---|---|
| 单首详情 | `getPoemById()` 第 428 行 | `db().collection('poems').doc(id).get()` — **云数据库 poems 集合** |
| 列表索引 | `fetchIndexFromDB()` 第 251–295 行 | 云数据库 `poem_index` 集合（6 分片，各~200KB，避开单次 1MB 上限） |
| 云存储兜底 | `fetchIndexFromStorage()` 第 297–308 行 | `index.json`，仅当 fileID 可解析时；**实测 `-403003 empty download url`，一直不可用** |
| 全文搜索 | `searchCloud()` 第 478–493 行 | 云数据库 poems 集合正则 |
| 单首缓存 | 第 36、422–425 行 | `wx.getStorageSync('poem_' + id)` 命中即返回，不再读云 |

**chunks/ 在整个小程序源码里零引用**。chunks 是生成端/云包目录概念，不是小程序运行时的数据源。文件头第 3–4 行明确写：为把 14.43MB 的 `utils/poems.js` 移出主包、压回 2MB 内，才改走云开发按需取数——`poems.js` 本地大文件都已经不用了，chunks 更不可能。

详情页 `pages/detail/detail.js` 第 42 行调 `getPoemSafe(id)` → `getPoemById`；第 75 行 `lecture: poem['串讲'] || ''` 把串讲字段直接渲染。`detail.wxml` 第 55–61 行 `<view class="lecture">{{lecture}}</view>`。字段链路完整。

## 三、这对三批 Upsert 意味着什么

- 三批清单（pilot30 / batch2 / batch3）各 30 行，共 90 首，`_id == id`（90/90 核过），且**只改 `串讲` 字段**、其余字段照旧。
- 导入到 `poems` 集合，选 Upsert（按 `_id` 更新），总数仍 7523。
- 导入成功后，新装用户 / 清过缓存的用户打开「黍离」「凯风」等，详情页会走 `collection('poems').doc(id).get()` 拿到新串讲并显示。
- **不需要传 chunks、不需要改小程序代码、不需要重新发版。**

## 四、关键坑：本地单首缓存不会自动失效

`getPoemById` 第 422–425 行：先读 `wx.getStorageSync('poem_' + id)`，**命中就直接返回**，不查云。而全项目**没有任何清理 `poem_` 缓存的代码**（grep 全库仅 poemsCloud.js 两处定义与使用）。

后果：如果某用户在 Upsert **之前**打开过某首诗，本地已缓存旧模板串讲；Upsert 之后他再打开，仍显示旧文本——**这是缓存陈旧，不是 Upsert 失败**。

### 真机验证的正确做法（避免误判）
1. 用一台**从未打开过**这些诗的设备/微信号，或
2. 验证前在微信开发者工具 → 清缓存 → 清除数据缓存（清掉 `poem_<id>`），或
3. 在小程序「我的」里退出登录/清本地数据后重进，或
4. 临时把 `getPoemById` 的缓存读取注释掉跑一次验证（改代码，需发版，不推荐仅为此）。

推荐 1 或 2。看到新串讲即证明 Upsert 成功；看到旧模板先怀疑缓存，再怀疑导入。

### 是否要修这个缓存坑（待枯木定）
可选做一个小修：给 `poem_` 缓存加版本号或时间戳（如 `poem_v2_<id>`，Upsert 后统一换 key），让老缓存自然失效。但这属于改代码+发版，**不在本批内容补齐范围内**，列作后续可选项。

- 三批操作卡里的"未确认项：小程序读云库还是 chunks"——**已确认为读云库，划掉**。
