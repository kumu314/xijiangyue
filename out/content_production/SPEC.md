## 字段规格（每首）

1. **串讲**（string）
   - 总长 **250–480 字**（口径：**非空白字符数，含中文标点**；下限由 280 调至 250，灵玉 batch-02 实测 283 均值下的合理密度）
   - 分 2–3 段，段间以 `\n` 分隔（起承转合或自然层），单段 ≤200 字
   - 引文一律「」，**允许跨句**：去标点后在该诗 lines[].o 整诗拼接串中子串匹配即可（词曲上下片、赋的跨句引文合法）
   - 禁 markdown；禁"首先/其次/总之"式套话**开头**（句中自然连接的「然后」不算违规，灵玉 #1456 自我更正确认）
2. **memory_new**（array，2–3 条，合入时替换 memory 数组）
   - `{t, d}`；t 受控词表：画面联想 / 结构抓手 / 意象锚点 / 名句锚点；每条 d **55–100 字**（同上字数口径）；合计 130–260 字；至少一处引用原诗字词
3. **不动的字段**：lines（o/m）、story、scenes、anim、tags、level、category；id 照抄
4. **译文线（qoder）**：拓展 m 实测 4880/4930 为空 → 量产=**从零补齐**而非改写；no_paraphrase 豁免清单：sishui_lyd、jiaowo_lbn（o 即白话，无从释译）；异文/疑难字按「o 一字不改」照抄并在批次 README 标注，校勘走 #61

## 质量与自检（每批必做，结果写进批次 README）

引文整诗串匹配 100% ｜ 串讲总量与分段 100% ｜ memory 条数/词表/长度 100% ｜ 抽样可复现（seed=批号+排除清单）｜ o 不变校验

## 批次规则

- 每批 30 首，seed=批号，id 与已发批次不相交（台账 LEDGER.md）
- ★ **筛池必须按 id 显式排除全部已发批，不得只靠「串讲字数 <200」**（2026-10-06 新增）：**已交付但未合入 index.html 的批次在库内仍是占位短句**，按字数字段筛会把它们重新选中 → **重复生产**。实测：已发串讲线 id 合计 **220**（pilot-01 30 + batch-02/03/04 各 30 + batch-05 40 + batch-06 30 + batch-07 30），而库内 `filled200` 仅 **120**，差值 100 全部来自未合入批次（batch-05/06/07）。字数字段只能当辅助判据。
- 抽检：灵玉按批 20%；**合入闸门**：抽检放行条件全部关闭后才可合入 index.html（batch-02 因送李端重复条目未合入，见 LEDGER）
- 合入：小羽 merge 脚本（串讲→串讲字段靠 .lead pre-line；memory_new→memory 整体替换）

## 抽检固定口径（灵玉 v2，2026-10-02 起，写死）

1. 机械项**全量复算**（15 项：id/重复/category/level 一致性、引文整诗串匹配、串讲总量与分段、memory 条数·词表·字数·引原诗、禁 md、禁套话开头），不做抽样——规则符合性是二值的。
2. 必跑**跨篇模板化检测**（2026-10-06 灵玉裁决，qoder batch-07 二检提出后统一）：归约后按 **n=12 字 n-gram 跨篇共用 ≥2 篇**即判模板——这是**主判据**；**整串相等**降为**辅证读数**，只记录、不单独定 PASS/FAIL（整串尺跑库内模板池同样得 0，两组都 0 时判据无分辨力，属「证据集装着自己」的错误模式，见 #62）。须带**注入自测**（把一句复制进另一篇，重跑应抓到 ≥1，抓不到即判据失效；不做自测的 0 一律不采信）；库内已知模板篇对照应得 ~40，判据分不开两组即判据无效。
3. 内容抽读按分类等比 20%，**必须覆盖最长与最短两极端**。
4. 数据缺陷记批次 README + 同步 #61/#55，并明确写「是否阻塞合入 + 理由」。
5. 报告一律 out/review-prod-batch-NN.md 入库。
6. **可用池唯一口径 = 选样脚本实测值**（2026-10-06 灵玉裁决）。README 里的算术推导（如 661−146=515）与卡面历史数字（475/476/496 互不一致）都不作口径源。每批交付时把池的**五个过滤条件 + 实测值**写进批次 README 头部固定字段：level / category / 已量产 `filled200` / 已发批 id / 阻塞名单；卡面与 LEDGER 引用实测值。历史批的池数字不回改。
7. **跨线 id 登记**（2026-10-06 灵玉裁决）：串讲线与译文线**允许**抽中同一篇——两线写的字段完全不相交（串讲线写 `串讲`+`memory_new`，译文线只写 `lines[].m`），**不设跨线去重**，但每批须在 README 列出跨线命中清单、LEDGER 登记。
   - **合入顺序无关**：已核实 `out/merge/merge_content.py` 是**按字段独立合入**（串讲→`set_kv`/`append_kv`、memory_new→memory 整体替换、lines[].m→**只重建原 lines 段**并带 o 漂移闸），两线合入互不干扰，**不存在「顺序反了互相看不见」的问题**。（此点初稿沿用了他人推测，核实后更正。）
   - **真正的风险是内容一致性而非合入**：同一篇的串讲与译文由两批人各写、互不知情，可能出现训诂/解读不一致。跨线篇在合入后应抽查「串讲说法 ↔ 译文训诂」是否冲突。
   - 实测（2026-10-06）：线内 id 重叠各批均 **0**；跨线重叠是系统性的——batch-02 8 首 / batch-03 11 首 / batch-04 6 首 / batch-06 9 首 / batch-07 6 首 / trans-06 5 首。

1. **串讲**：以现有短串讲**为骨架扩写**到 250–480 字、2–3 段、单段 ≤200 字。保留原串讲的判断与措辞颗粒，**不得推翻重写**。引文一律「」，去标点后在本篇 `lines[].o` 整诗拼接串中子串匹配（与拓展线同）。

5. **曲类冻结**：精读曲 24 篇（串讲中位仅 18 字）与拓展曲同理由冻结，等 #61 曲类手术（裸曲牌 20 首 / 双标点 8 处 / 串烧篇）完成。⇒ **精读线实际待办 183 篇**（诗 128 + 词 44 + 赋 11）。
