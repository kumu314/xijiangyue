### 修掉的真 bug
`buildDailyTasks` 原先不防重：异常态（指针回退 / 清了 pointer 未清 review / 队列手工注入）下，温故 pick 与新学指针撞同一 id，会在"今日任务"里推两张同一首诗——正是 #347 要消灭的假进度体感。修复：新学侧用 `used` set 跳过已用 id，p2 继续跳过外国诗与已用 id。

**反向注入证据**（新断言必须会红）：用修复前备份 `reviewQueue.js.bak-20261126-dedup` 经 `RQ_PATH` 注入跑同一脚本 → `PASS=50 FAIL=1`，红的正是 C11；正式版 `PASS=51 FAIL=0`。断言非空转。

## 四、双端口径的已知差异（如实记录，非缺陷）
1. 小程序 `reviewable` 额外排除 `category==='外国诗'`；web 只看 `orig_lang!=='zh'`。小程序更保守，方向一致。
2. web 到期队列取前 `REVIEW_DAILY_CAP=10` 首；小程序一屏只推 1 张温故卡（top1），cap 常量保留但当前不参与裁剪。
3. web 无到期时显示"今日无到期"；小程序按枯木拍板②随机回看一首已学诗，是阶段一新增语义。
4. 入队触发：web = 遮字全部揭示（通背）才入队；小程序 = 「记」打卡即入队（Stage 1 约定，Stage 2 背诵模式移植后由原语义接管）。
