## 二、问题①判词：去重达成，但引入"新学卡归零"副作用

### 2.1 实测四场景（`probe_review_dedup_347.cjs`，只读调 `buildDailyTasks`）

| 场景 | 任务形状 | 新学卡数 | 重复 |
|---|---|---|---|
| S1 空队列、指针 q00（正常基线） | q00(new)+q01(new) | 2 | 无 |
| **S2 pick=q00 且指针=q00（正面撞，即 C11 场景）** | **仅 q00(review)** | **0** | 无 |
| S3 pick=q01 指针=q00（指针 p2 撞） | q01(review)+q00(new)+q03(new) | 2 | 无 |
| S4 pick=q00 指针=q01（温故撞 p2） | q00(review)+q01(new)+q03(new) | 2 | 无 |

**S2 是关键反例**：小羽自报"仍是 2 张"，实测是 **1 张（0 张新学）**。

### 2.2 根因（打开代码本体，reviewQueue.js 第 198–209 行）

```js
var p1 = pointerPoem(indexArr);
if (p1 && used[p1.id]) p1 = null;     // 撞了 → p1 置 null
if (p1) {                             // p1 为 null → 整块跳过
  ...p2 顺延逻辑写在块内...            // 因此 p2 永不执行
}
```
`p2` 的 `while` 顺延写在 `if (p1)` **内部**。p1 撞 id 被置 null 后，`if (p1)` 整块不进，顺延逻辑根本没有执行机会——这正是 S2 新学卡归零的直接原因。

### 2.3 C11 为什么没拦住（断言覆盖不足）

C11 原文：`eq(new Set(ids).size, ids.length, 'C11')`——只验"当日任务 id 无重复"。S2 输出 1 张卡、set size=1=length，**满足断言**。也就是说：C11 能证明"不再出两张同一首"，**不能证明"新学卡仍在"**。反向注入（旧备份出 q00/q00/q01 三张）红的是同一条断言，说明这条断言的语义只是"无重复"，与"任务数达标"是两件事。

### 2.4 定性、影响与修法方向（我只读不改，方向供 doer 参考）

- **定性**：真缺陷，但触发面限异常态（指针回退 / 清了 pointer 未清 review / 队列手工注入）——小羽报告 §三自己写"正常流程不会"。正常态（新指针 q00、队列里是更早背过的 q01+）不撞，S1/S3/S4 均正常出 2 张新学卡。
- **影响**：异常态当日"今日任务"只剩温故卡，新学进度停一天。不会双计进度（去重目标达成），但用户体感是"今天没新诗学"。
- **修法方向**（doer 自行判断，我不代改）：把 p2 顺延的 `while` 提到 `if (p1)` 之外，或在 `p1=null` 时用 `pos2=当前指针位` 起跳再顺延；并补一条断言"撞 id 后新学卡数 ≥1（或任务总数 = 1 温故 + 2 新学）"。补断言后用旧备份再注入，应同时红 C11 与新断言，才算把副作用关住。
- **失效边界**：若枯木裁定"异常态出 1 张温故卡可接受"，那本条降为已知限制、不必修——但需在报告 §四登记，且 C11 的自报措辞"仍是 2 张"仍须更正为实测读数。

## 三、问题②判词：四条双端口径差异逐条

| # | 差异（小羽 §四原文） | 我的判词 | 依据 |
|---|---|---|---|
| 1 | 小程序多排除 `category==='外国诗'`，web 只看 `orig_lang` | **必须拉回同构（方向：小程序对、web 漏挡）**，非"等价保守差异" | 云数据实测：117 首外国诗中 **15 首缺 `orig_lang`、1 首标 `orig_lang='zh'`**，web `reviewable(p)= !(p.orig_lang && p.orig_lang!=='zh')`（index.html:78259）挡不住这 16 首，会把外国诗温故；小程序 `isForeign()` 多一条 category 判断，正好挡住。非外国诗 orig_lang 非 zh 的为 0，说明小程序的 category 排除是纯增益、无误伤 |
| 2 | web 到期取前 cap=10；小程序一屏推 1 张（top1），cap 常量保留但不裁剪 | **可接受差异** | 一屏 1 张是小程序卡片形态约束（learn.wxml 单卡位），非口径错误；due<=today 判定与排序两端一致（B5–B7 + 我读 web:78308–78318）。积压消化速率差异（web 日清 10 vs 小程序日清 1）属产品取舍，枯木拍板②"指针为主"未要求追平 cap |
| 3 | web 无到期显示"今日无到期"；小程序随机回看 | **可接受差异** | 枯木 11-26 拍板②明确授权"无到期时随机兜底"，是阶段一新增语义，不是口径漂移 |
| 4 | 入队触发：web 遮字通背才入队；小程序「记」打卡即入队 | **可接受，但须登记为分阶段约定** | reviewQueue.js 头注第 9–10 行、learn.js:245–248 均写明"Stage 2 背诵模式移植后原语义接管"；这不是永久分叉，是明确交接。风险：若 Stage 2 未落地就发布，两端入队门槛持续不一致；应在阶段二验收门加一条"入队触发回归 web 语义" |

小结：小羽 §四把四条一律记"非缺陷"偏乐观——第 1 条是 web 侧真漏挡（16 首），第 4 条是带交接条件的暂态差异。其余两条可接受。
