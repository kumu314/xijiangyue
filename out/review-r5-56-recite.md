## 3. 独立核查（小羽断言没覆盖到的角度）

### 3.1 遮蔽率实测 = 设计值（全库 970 首 / 5787 行 / 77495 token）

```
档位1  被遮 19325 (24.9%)   档位2  被遮 38690 (49.9%)
档位3  被遮 58105 (75.0%)   档位4  被遮 71711 (92.5%)
```

三档与设计的 25/50/75 **完全吻合**，说明 `hash32 % 100` 阈值法分布均匀、无偏。✓

### 3.2 ★ `touchReview` 在 `openDetail` 里**无条件**调用 —— 与提交信息不符

代码：`openDetail()` 渲染完正文后直接 `touchReview(p);`，**不看档位**。
实测：清空 `xjy_review` → 只 `openDetail('t_guren')`（**档位仍为 0，一次都没点「背诵」**）→ 队列变为 `["t_guren"]`。

而提交信息写的是「**首次开档即记录**」。

**影响**：这决定了 ② 温故队列的语义 —— 是「**所有点开过的诗**」还是「**背过的诗**」。前者会把队列撑得很大（用户随手点开即入队），虽有 §②「每日上限 10 首 + 超期降档」兜底，但「点开过」≠「该复习」。
**建议**：二选一定死并写进 SPEC —— (a) 若确实要「开详情即入队」，改提交信息即可（我认为这是合理设计：读过就该温）；(b) 若按字面「开档才入队」，把 `touchReview` 挪进 `maskOn` 分支。

### 3.3 标点/空白会被遮，占比 ~16%

`tokenize` 对中文按字切分，标点也是 token，同样走 hash 判定。全库实测：

| 档位 | 被遮 token | 其中标点/空白 | 占被遮比 |
|---|---|---|---|
| 1 | 19325 | 3097 | 16.0% |
| 2 | 38690 | 6132 | 15.8% |
| 3 | 58105 | 9130 | 15.7% |
| 4 | 71711 | 12139 | 16.9% |

即**每遮 6 个字就有一个是标点**（静夜思档位 3 的「。」就被遮）。全遮档除每行首字外一律遮，含标点。
**建议**：背诵时标点通常应作结构提示保留（`tokenize` 里对 `PUNCT` 直接 `keep`）。非阻断。

### 3.4 记忆卡内容感知：覆盖完整（独立普查）

```
level 分布: {精读: 260, 拓展: 710}
拓展篇 710 首 → 有 memory 710 / 无 memory 0
  含模板句式(它是全篇的眼|每天慢读三遍): 710
  不含模板句式（会渲染出原文 → 漏网）: 0
  部分含模板（some 判定会整条吞掉）: 0
拓展篇 memory 的 t（标题）去重数: 2 → ["主线串记","以声入心"]
```

两个模板句实为：
- `t=主线串记`：「先抓住「XX」这一句（它是全篇的眼），再按「意象—情绪—哲思」的层次逐段背，比死记全篇牢得多。」
- `t=以声入心`：「每天慢读三遍，靠韵脚与节奏自然成诵，不必硬背。」

**正则覆盖面 100%，`some` 判定无副作用。** ✓

> ⚠ 但这是**内容嗅探**：内容量产合入真卡后，若某张真卡恰好含这两句会被误吞。
> **建议**：量产合入时改用显式标记（如 `memory_src:"template"`），正则只作过渡。

### 3.5 竖排下的遮字标记：布局未破，但观感偏「破折号」

`.ch.masked` 用 `background-image:linear-gradient(to top, rgba(178,58,46,.55) 0 2px, transparent 2px)` —— 画在**盒底**的 2px 横线。在 `writing-mode:vertical-rl` 下，每个字下方出现一短横。
我看了截图 `out/r5-recite/01-竖排中文-遮二.png`：**布局未破、字距行距正常、无重叠**，观感可接受；但该短横在竖排里读起来接近「—」，与标点混淆的风险存在。
**建议**：竖排时改用随书写方向走的方案（`border-inline-end` / `text-decoration`），或接受现状并在 SPEC 记录。非阻断。

### 3.6 「遮蔽集只增不减」在 3→4 档对**每行首字**不成立

档位 0→1→2→3 严格单调（我已逐 token 验证：每档被遮集 ⊇ 上一档）。
但档位 4 换成了另一套机制（首字诀：`pos===0` 保留），于是**每行首字**可能出现「档位 3 已遮 → 档位 4 变可见」。静夜思实测第 13 个 token（第二行首字「举」）即为此例。

**建议**：把首字诀并入同一规则（对首字单独放行），或把口径改述为「**0→1→2→3 单调；4 档改首字诀**」，避免复核者按字面「只增不减」判错。非阻断。

### 3.7 `tokenize` 的语种判定是「整行含拉丁/希腊/西里尔/假名 → 整行走词切分」

实测中文诗里有 **3 句**含假名「タ」，会整块遮而非逐字：

```
[yq_c69de3e2] 正宫·塞鸿秋代人作  「起初儿相见十分砒タ，心肝儿般敬重将他占。」
[yq_b39e7036] 越调·凭阑人题情    「懒对菱花不欲拈，愁理晨妆不甚タ。」
[yq_b39e7036] 越调·凭阑人题情    「红叶传情着意拈，书遍相思苦未タ。」
```

**顺带发现数据问题**：这 3 句的「タ」经码位核对确为 **U+30BF KATAKANA LETTER TA（日文片假名 ta）**，元曲文本里出现片假名，**必为 OCR 讹字**：

```
起初儿相见十分砒タ，心肝儿般敬重将他占。   ← 「砒タ」
懒对菱花不欲拈，愁理晨妆不甚タ。           ← 「不甚タ」
红叶传情着意拈，书遍相思苦未タ。           ← 「苦未タ」
```

据韵脚（与「拈」押韵，需平声）与文义，疑当作「**忺**」（xiān，适意、高兴；「甚忺」= 很惬意，「苦未忺」= 苦犹未足）。**存疑，请数据方裁定**，我不擅自改。建议进数据修复队列 —— 这不只是遮字问题，本身也是文本错误。
