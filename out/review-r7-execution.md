## 3. 过程中拦下的一个真实设计冲突（最值得记的一条）

**现象**：P2-4 初版把纸纹噪声当背景层挂到 `.hero`（`--paper-noise-05/08, --hero-grad`）。

**为什么危险**：round5 §2.2 记录的最紧对比组正是 hero —— heroB `#F6EEDC` + 黑色意象@.15 得 `#D1CABB`，
`--ink-2` 对比 **4.68**，距 AA 4.5 只剩 **0.18**。噪声最暗粒子（≈纯黑 × α）会把这个底再压一档：

| 档 | 噪声 α | 叠后底（估） | `--ink-2` 对比 | 判定 |
|---|---|---|---|---|
| 关 | 0 | `#D1CABB` | 4.68 | 余量 0.18 |
| 淡 | .05 | ≈`#C7C0B2` | ≈4.22 | ❌ 跌破 4.5 |
| 浓 | .08 | ≈`#C0BAAC` | ≈3.95 | ❌ 跌破 4.5 |

**处置**：按任务卡「宁砍不移」，`.hero` **一律保持纯渐变，不挂纸纹**，并在 CSS 就地写了注释防止后人加回去。
纸纹效果改由「整页底 `.phone::before`」+「阅读面 `.original`」两处承载 —— 观感目标不变，底线不破。

**验证**：hero 在关/淡/浓三档下截图**逐字节相同**（84350 px 内 0 像素差异），即本轮对意象底的增量为 **0**。

## 4. 两个必须如实说清的口径问题（不粉饰）

### 4.1 hero `--ink-2` 实测 4.60，与 round5 模型值 4.68 差 0.08

- round5 是**模型值**：按「最暗渐变停止色 + 统一黑@.15」手算。
- 本次是**像素实测**：真实渲染还叠了径向朱砂微染与抗锯齿抖动。
- **两者不可相减，也不是回归** —— 本轮增量为 0（§3 逐字节证明）。但**余量按实测只有 0.10，不是 0.18**。
- 处置：断言守 AA 4.5 硬线 + 零增量，差值在此显式上报，**不做四舍五入**。建议后续调 hero 渐变前先复测此组。

### 4.2 首次像素取样曾出现 `--ink-2 = 3.14` 的假 FAIL

原因：取样框含了 `.hero::before` 那条 `inset:6px` 的 **1px 朱丝内框**（`rgba(178,58,46,.30)` 叠出 L≈0.39），
它是该区域最暗像素，却**不承载任何文本**。取样内缩 10px 后回到 4.60。
→ **凡是"背景对比度像素取样"，必须先划掉装饰性线条/边框，否则量的是装饰不是底。**

## 6. 前提与失效边界

**前提**（不成立则结论作废）：
1. Chrome 153 + 390/375/428px 视口 + 系统默认字体族。字体降级链命中不同字族时，竖排容量会变（`vColUnit()` 已按实测容量自适应，但极窄字体下 `cap` 下限被钳在 4）。
2. 纸纹是 CSS data-URI 噪声，依赖 `feTurbulence` 支持（微信 X5/近三年 Chrome 均可；老 Android WebView 可能不渲染噪声，此时退化为纯渐变，不影响对比度与布局）。
3. 云同步的 `settings` 字段需后端已跑过 `ALTER TABLE`（已做幂等补列，老库自动补）。

**失效边界**（已知不覆盖）：
- **未在真机/微信内置浏览器验证**（本轮只跑桌面 Chrome）。
- **未验证 iOS Safari** 的 `background-image` 多层 data-URI 性能。
- 极长诗（>40 句）与「分段背诵」叠加竖排折行的组合**只做了逻辑一致性检查**，未做逐屏目视。
- 纸纹在三档下的**主观观感**（是否"够纸感"）未经枯木目视确认。
