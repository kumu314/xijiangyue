# 打卡「完成」反馈调研 · 从「换个配色」到「做出一记手感」

> 关联卡片：#199 P2-3（完成态向淡墨收敛）→ 枯木反馈「A/B 差点意思」
> 交互小样：`out/r7-mockups/checkin-feedback-abc.html`（可点、可听、可切 reduced-motion）
> 日期：2026-10-26｜执行：小羽

---

## 0. 一句话结论

A/B 之所以「差点意思」，是因为它们**只改了静态配色，一条反馈序列都没动**。
完成动作的爽感不来自「完成后长什么样」，来自**点击后 0–460ms 内同时发生的那几层反馈**。
建议：**B 落印**做日常反馈，**C 满勤卷**做 5/5 的仪式层；A 作为「怕吵」时的降级档保留。

---

## 0.5 不动的代价（先摆基线，免得"为了做而做"）

**维持现状是合法选项。** 现实必须写清：

| 维度 | 不动会怎样 |
|---|---|
| 功能 / 上架 | **零影响**。打卡能勾、能存、能同步、能过审。不改也能上架。 |
| 对比度 / 无障碍 | **零影响**。现有完成态本就过 AA。 |
| 产品气质 | 玉绿完成态与朱砂同屏的**冷暖割裂继续存在**（这正是 P2-3 原始议题，与反馈强弱无关）。 |
| 习惯养成 | 完成瞬间的确认强度弱 → 「因打卡而期待下一次」那点驱动力拿不到。**这是唯一实质损失，且难以量化。** |
| 可逆性 | 越晚做返工面越大：反馈要接进打卡卡、印谱、满勤、分享卡四个面。 |

**判断**：这一件的收益是**软收益**（体验与留存倾向），没有硬指标能证明它「必须做」。
如果你近期的主线是**上架与获客**而不是打磨留存，**完全可以先不做**，把预算压在别的件上。
我给出方案不等于我主张立刻做 —— 这笔钱花不花，取决于当前阶段目标是「能上线」还是「留得住」。

## 1. 调研：这类反馈到底靠什么起效

> ⚠️ 口径声明：下面这些数值与结论来自**设计规范转述与科普报道**，**不是一手实验**。
> 我没有做真人 A/B，也没有条件测量多巴胺。凡带「约/据说」的，都请当**经验值**而非定律。

### 1.1 结构：一次微交互的四个零件

Dan Saffer《Microinteractions》的四要素模型，是被引用最多的框架：

| 零件 | 含义 | 本项目的现状 |
|---|---|---|
| **Trigger** 触发 | 用户点击 / 系统状态变化 | ✅ 点击 `.ci-item` |
| **Rules** 规则 | 触发后发生什么、顺序如何 | ⚠ **只有一条**：换底色 + 印入场 |
| **Feedback** 反馈 | 视觉 / 听觉 / 触觉 | ⚠ 只有视觉，**无声音、无触觉** |
| **Loops & Modes** 循环与模式 | 反复点击时怎么变、满勤怎么变 | ❌ 每次一样，**没有「这一次不一样」** |

**这就是「差点意思」的结构性原因**：Rules 只有一条、Feedback 只有一个通道、Loops 完全没有。

### 1.2 时序：为什么「慢一点」就废了

| 时长 | 适用 | 来源 |
|---|---|---|
| 100–150ms | 悬停、按下等即时反馈 | 设计规范转述（Material 系） |
| 200–300ms | 绝大多数 UI 转场 | 同上（被反复引为「甜点区」） |
| 300–500ms | 较大转场、面板推出 | 同上 |
| >500ms | 罕见，仅当动画本身在传达重要信息 | 同上 |

另有二手报道称：**反馈若延迟超过 2 秒，激励效果衰减超 70%**（数据源为科普文，未见原始实验，仅作量级参考）。
→ 落地结论：**完成反馈必须全部落在 500ms 内**，满勤仪式可以稍长（1.4s），但日常点击不能拖。

### 1.3 多巴胺：是「预期」分子，不只是「奖励」分子

多篇科普与一篇被广泛转述的神经科学综述（*Journal of Neuroscience*, 2021 口径）都指向同一件事：
多巴胺主要在**预期奖励**与**预期被确认**这两个时刻释放，而不是「拿到奖励」那一刻。

对本项目的直接含义：
- **点下去的瞬间要有"要发生了"的预感**（按下压缩 1px，就是最小成本的预示）
- **确认要够快、够清楚**（印落定 + 计数跳变，双重确认）
- **变率提升预期强度**（详见 1.5）

### 1.4 情感化反馈 > 功能性反馈

Duolingo 的猫头鹰在被反复分析的点是：**答对时它真的"为你高兴"**，连续多天完成时庆祝会变得更热情。
分析文章的共同结论是：这类反馈把「使用产品」和「正向情绪」绑定，形成情感记忆。

注意：本项目**没有角色 IP**，也不该硬造一个。可替代的做法是 —— **用"物"承担情感**：
印章就是我的猫头鹰。它落下来，就是"这一下被记下了"。

### 1.5 变率奖励：好用，但有红线

Skinner 的变率强化（variable ratio）是所有奖励排程里**行为最持久**的一种，老虎机、抽卡、掉落都用它。

**但本项目不该照搬。** 理由：
- 用户群包含青少年，诗词产品不是消费型娱乐产品；
- 「随机掉大奖 / 概率翻倍 / 抽卡」会制造**必须每天来刷**的强迫感，与「读诗养性」的产品气质直接冲突；
- 长期看，赌博式机制被识破后会反噬信任。

**折中方案（我建议采用的）**：把变率放在**内容**，不放在**奖励强度**上。
即：满勤时给**一句随机且不与上次重复的题跋**。用户不知道今天抽到哪句 —— 预期被激活了，但没有「这次亏了」的挫败，也没有「必须再刷一次」的钩子。

### 1.6 另外两个已经在用、但没用满的心理学杠杆

| 杠杆 | 现状 | 可补的 |
|---|---|---|
| **Zeigarnik 效应**（未完成制造张力） | 有「还差 N 项」，但一直淡灰小字 | 剩 1 项时**升级为朱色强调**（小样已实现：`还差 1 项，今天就能满勤` 变红） |
| **损失厌恶**（streak） | 有连击数，但完成瞬间不给「保住了」的确认 | 满勤时把 streak 一并点亮（本轮未做，见 §6） |

## 2. 现状反馈的三处「漏气」（这是判断依据，不是感觉）

对照 `index.html` 现有实现（`.ci-item` / `stampIn` / `inkSpread` / `toast`）逐条查：

| # | 漏气点 | 具体表现 | 后果 |
|---|---|---|---|
| 1 | **只有一层动效** | 印 0.45s 缩放旋转 + 0.6s 径向光晕，`::after` 光晕还被 `overflow` 与层级压住 | 视觉上像「贴纸淡入」，没有「落下」的重量 |
| 2 | **声音与触觉完全缺席** | 无任何音频，无 `navigator.vibrate`（小程序侧也没有 `wx.vibrateShort`） | 少了两个通道，只剩眼睛在确认 |
| 3 | **确认被 `toast` 抢走注意力** | 点完屏幕底部弹通用灰 toast「已打卡 ✦」 | 注意力被拉离现场，**仪式感在最高点被打断** |
| 4 | **完成态是"被染色"而不是"被盖上"** | 玉绿底 + 玉绿描边 + 玉绿勾 | 玉绿与朱砂同屏冷暖割裂（P2-3 原始问题），且没有「盖上去了」的实感 |
| 5 | **没有任何"这一次不一样"** | 第 1 次和第 100 次点击完全一致 | Loops 为空，习惯养成最缺的那口没给 |

## 3. 三个方案（都在小样里可以点）

小样：`out/r7-mockups/checkin-feedback-abc.html`
顶部可切方案 / 开关音效 / 勾「模拟 reduced-motion」看降级效果。音效全部 WebAudio 实时合成，**零音频素材**。

### 方案 A · 朱批（最克制）

只动「点」与「晕」，**不引入任何位移元素**。

| 时间 | 发生什么 |
|---|---|
| 0ms | 按下：卡片下陷 1px、缩到 98.5% |
| 0–120ms | 勾选圈由空心转朱实心；一圈朱色向外晕开到 2.6 倍后消散（380ms） |
| 60–360ms | 卡片底色由朱色 radial 从圆点位置渗开（替代玉绿） |
| 180–360ms | 顶部计数滚轮上翻一位 |
| 音 | 一声极轻高频「哒」（1450→760Hz，70ms） |

**气质**：文人批点，安静、耐看，一天点五次也不吵。
**风险**：爽感偏弱。如果你要的正是「点下去有点上头」，A 不够。

### 方案 B · 落印（**推荐**）

一次落印 = **四层同时发生**，爽感来自叠加而不是夸张。

| 时间 | 发生什么 |
|---|---|
| 0ms | 按下：卡片下陷 1px、缩到 98.5% |
| 0–260ms | 印从 **2.35 倍**高砸下，带 1.4px→0 的模糊（模拟入纸），过冲到 93% 再弹回 106% → 100%（overshoot） |
| 40–320ms | **6 粒朱砂**沿印边向外飞散（每粒随机角度/大小 1.6–3.4px/延迟 13ms），300ms 淡出 |
| 80–460ms | 墨晕从印位向卡片扩散到 2.2 倍并淡出；卡片底色同时转**淡墨**（`rgba(43,38,32,.032)`）+ 墨色描边 |
| 200–380ms | 计数滚轮上翻 |
| 音 | 「**笃**」：210→96Hz 下滑正弦 + 8ms 高频纸面噪声 |

**为什么爽**：视觉是「重物落下 + 碎屑飞散」，天然带触觉记忆；听觉是低频冲击；两者同一帧起手 → 大脑判为「一件事真的发生了」。
**成本**：纯 CSS + 极少 JS 生成粒子，**无图片、无音频素材**，预估新增 CSS ≈1.6KB / JS ≈0.8KB。
**无障碍**：颜色之外还有「印的存在」+ 勾选形状，色弱可辨；颜色永不作为唯一信号。

### 方案 C · 落印 ＋ 满勤卷（进阶）

日常点击**完全同 B**（关键：日常反馈不能因为「可能满勤」而变慢）；只有 5/5 那一刻多一层：

| 时间 | 发生什么 |
|---|---|
| 满勤瞬间 | 卡片下方卷轴从 0 展开到 64px（420ms），一句随机题跋淡入上移 |
| +240ms | 「**磬**」：880 / 1320 / 1760Hz 三个正弦叠加，1.35s 长衰减 |
| 变率 | 题跋从 5 句池随机，且不与上一次重复 —— **变率在内容，不在奖励强度** |

**为什么值得做**：日常给爽感，满勤给一个「今天不一样」的记忆点。这是留存真正吃的那一口。
**边界**：刻意**不做**随机大奖 / 抽卡 / 概率加倍（理由见 §1.5）。

## 4. 我的推荐与理由

**推荐 B + C 组合，A 保留为设置项里的「动效：克制 / 标准」二档。**

理由：
1. **B 的每一层都有功能，没有一层是装饰** —— 砸下=「记下了」、溅点=「刚发生」、墨晕=「盖上去了」、计数=「进度变了」。符合「动效要么传达信息，要么砍掉」。
2. **B 不引入任何图片/音频资产**，对小程序 2MB 主包零压力（音效小程序侧需换 `wx.createInnerAudioContext` 或跳过 —— 见 §6）。
3. **C 只在满勤触发**，不给日常增加延迟，符合 §1.2 的时序纪律。
4. **A 作为降级档**，给「嫌吵」的用户和老年用户一条退路，同时天然满足 reduced-motion 之外的第二层克制需求。

**如果你只想要一样**：先做 **B**。C 可以下一轮再加，B 已经能补掉 §2 里 5 个漏气点中的 4 个。

## 5. 与硬验收门的对齐（这套改动不会破坏已过的门）

| 门 | 这套设计的处置 |
|---|---|
| prefers-reduced-motion 全覆盖 | 降级后**只保留「状态变化 + 计数」**，不加任何位移/粒子/模糊；音效保留（声音不属 motion），但可随系统「减弱动效」一并关闭 |
| 新增色 AA 对比度 | 不引入新色。朱砂 `#B23A2E`、墨 `#2B2620` 都是既有令牌；淡墨底 `rgba(43,38,32,.032)` 只压暗约 3%，需在落地后复测该组对比度 |
| 意象底余量 0.18 不压缩 | 完全不碰 `.hero` |
| 首页零新增区块 | 全部落在学习页打卡卡内，首页不动 |
| 宁砍不移 | 冲突时砍粒子（B 可退化为 A 的手感），不砍对比度与 reduce 降级 |
| 断言先行 | 落地前把时序、降级、色弱冗余写成断言（含 `animation-duration` 逐项核对） |

## 6. 落地成本与已知阻碍（说清楚，不藏）

| 项 | 桌面 HTML | 微信小程序 |
|---|---|---|
| CSS 动效 | 直接可用 | 可用（WXSS 支持 keyframes/transform） |
| 粒子生成 | JS 创建 span | 可用，但需注意 `setData` 频率 → 改直接操作节点或预置节点显隐 |
| 音效（WebAudio） | 直接可用 | ❌ 不可用。需换 `wx.createInnerAudioContext` + 真实音频文件（体积成本），或**先不做音效** |
| 触觉 | `navigator.vibrate`（安卓部分支持，iOS 不支持） | `wx.vibrateShort({type:'light'})` ✅ 更好，**建议小程序侧用这个替代音效** |

→ **建议：桌面端做「动画 + 音效」，小程序端做「动画 + 轻震」**。同一套设计，两个通道。
→ 小程序侧落地前需要枯木拍板一件事：**是否接受首次使用时请求音频权限 / 是否干脆只用震动**（我倾向只用震动，省权限弹窗）。

## 7. 未检查项（明确列出）

1. **没有真人 A/B 测试**。所有「更爽」的判断基于设计规范与行为心理学的转述，不是本产品的实测留存数据。
2. **没有测帧率**。B 的 6 个粒子 + 2 个 radial 在低端安卓上是否掉帧，未验证。
3. **音效音量未校准**。目前增益是我估的（笃 .34 / 哒 .10 / 磬 .18），实际在手机外放上是否刺耳未测。
4. **iOS Safari 的 WebAudio 解锁路径**未在真机验证（需用户手势后 `resume()`，代码已写但没真机跑）。
5. **streak 的「保住了」确认**未做（§1.6 下半部分），列为下一轮候选。
6. **A/B/C 的方案选择本身没有数据支撑** —— 这正是需要枯木拍板的部分。

## 8. 需要枯木拍三件

1. **选方案**：A / **B**（推荐）/ C（B+C 组合）。
