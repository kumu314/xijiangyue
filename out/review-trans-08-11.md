### 3.1 量具纠错与修复（本报告自查，重要）

诊断脚本 `verify.py`（位于 `D:/AgentHub/temp/xjy-trans1218-lingyu/`，**不是仓库文件**）对 trans-08~11 曾跑出 **184 / 206 / 213 / 181 处** 跨篇命中，看似 FAIL。经定位，**这是诊断脚本的 bug，不是真模板**：

- `verify.py` 构建 `prior` 时 `for b in ['qoder-01'] + [f'trans-{i:02d}' for i in range(1, 12)]` 把**当前批自身**（如 trans-10）也算进 prior；它只对 12~18 段排除了 `BN`，漏排了 1~11 段。于是 BN∈{08..11} 时 = 用自己的句子比对自己 → 产生 180–210 假命中（n=8 与 n=12 计数完全相同，正是「整句自匹配」而非真 n-gram 命中的特征）。
- **仓库生产工具 `out/review-tools/n8_counter.py` 本身正确**（第 215 行 `for b in names if b != a` 已排除当前批），故正式/线上抽检的反模板读数不受影响，只有这个临时诊断脚本会误报。
- **已修复**：`verify.py` 在 1~11 段跳过当前批（`BN_ID`），并顺带修了文件名零填充 bug（`trans-9` → `trans-09`，否则 trans-01~09 根本读不到文件）；`anti_tpl.py` 也加了「对照集排除目标批」的显式守卫（此前只是靠 `BATCHES=12~18` 与 `PRIOR=1~11` 不重叠而侥幸不自匹配）。
- **修复后实测**：trans-8 / trans-9 / trans-10 的 n=12 与 n=8 跨篇命中**全部 0 处 PASS**，实质率与 §2 完全一致（93.97 / 80.26 / 87.83%）。⇒ 本报告反模板结论（0 处）以修复后的脚本复现，成立。
