## 2. P0 —— 外国诗详情横向溢出，「背原文」按钮在屏外

### 实测

```
07-detail-foreign（野玫瑰）：#views scrollWidth 428 / clientWidth 390 → 溢出 38px
overflow-probe（sonnet18）：#views scrollWidth 469 / clientWidth 390 → 溢出 79px
```

其余 7 个状态 `overflow = 0`。**仅「有原文附注的外国诗」触发。**

### 根因定位（`overflow-probe.mjs` 逐元素扫描）

```
#reciteBtn  [btn read-btn] "背原文"  left=400  right=469   ← 完全在屏外
```

`index.html:108`：

```css
.detail-head{display:flex;align-items:center;gap:12px;margin:4px 0 16px;}
.detail-head .read-btn{margin-left:auto;}
```

详情页头部一行塞了 5 项：`.back`(36) + 标题块 + 听朗读(77) + 竖排 + 背诵 + **背原文(69)**，`gap:12`。
`背原文` 在 `index.html:69558` 由 `hasOrig` 控制显隐——**只有外国诗才显示**，一显示就超出 390px。
标题块没有 `min-width:0` / `overflow:hidden`，不参与收缩；4 个按钮又各带 `margin-left:auto`，空间无从腾出。

### 影响

`.views{flex:1 1 auto;overflow-y:auto}` —— `overflow-y` 非 `visible` 时 `overflow-x:visible` 按规范计算为 `auto`，
所以**整个内容区变成可横向拖动**。用户要么永远发现不了「背原文」，要么在竖排诗卷上误触发横向拖动，与竖向阅读手势打架。

### 建议修法（任选，按推荐度）

1. **止血（一行）**：`.detail-head{flex-wrap:wrap;row-gap:10px}` + `.detail-head .read-btn{margin-left:0}` +
   `.detail-head .read-btn:first-of-type{margin-left:auto}` —— 按钮组空间不足时换行，不再顶破容器。
2. **根治**：390px 下这一行即使标题缩到 0 也几乎没有余量——实测 `back 36` + `背原文 69` + `听朗读 77`，
   再加 `gap:12×4=48`，已知三项合计 230，剩 160px 要放标题 + 竖排 + 背诵两个按钮（后两个按 ≈66 估算则标题仅剩 ≈16px，故为估算值）。
   结论方向不受估算影响：**4 个带文字按钮在 390px 下没有余量**。
   建议把「背原文」收进「背诵」按钮的次级菜单/长按，或窄屏下按钮只留图标。
3. 兜底：`.detail-head > div:nth-child(2){flex:1 1 auto;min-width:0}` + `.dt{white-space:nowrap;overflow:hidden;text-overflow:ellipsis}`，让标题先让位。

## 3. P1 —— 40 首「精读」用模板变体绕过检测器，伪装成完整内容

这是本次**最需要被看到的一条**：它不是内容缺失，而是**空洞被伪装成了完整**。

### 代码里的检测器（`index.html:69570-69571`）

```js
// 拓展篇 memory 多为内容量产模板（「它是全篇的眼」/「每天慢读三遍」两句式），非人工记忆卡 → 不渲染模板文本
const memTpl = expand && (!mem.length || mem.some(m=>/它是全篇的眼|每天慢读三遍/.test(m.d||"")));
```

命中则渲染诚实的「记忆要点待补」卡。注意两个约束：`expand &&`（**只对拓展生效**）和硬编码字符串 `每天慢读三遍`。

### 实测：量产模板存在两个变体，只差一个字

| 层级 | 篇数 | 记忆卡末句 | 是否被检出 | 用户看到 |
|---|---|---|---|---|
| 拓展 | 710 | 「每天**慢**读三遍」 | ✅ 命中 `每天慢读三遍` | 「记忆要点待补」+ 引导用遮字自测 |
| **精读** | **40** | 「每天**读**三遍」（无「慢」） | ❌ 逃逸 | **量产模板被当作真实记忆卡展示** |

40 首全为外国诗（`byCat: {外国诗: 40}`），篇名包括：
野玫瑰、漫游者之夜歌、乘着歌声的翅膀、罗雷莱、致云雀、她走在美的光影里、夜莺颂、秋日、豹、
我是怎样地爱你、飞鸟集（节选）、**世界上最遥远的距离**、先知（节选）、沙与沫（节选）、醉舟、
黄昏的和谐、青春、梦游人谣、海涛、春的临终、致凯恩、自由颂、帆、我愿意是急流、人生礼赞、
未选择的路、自我之歌（节选）、因为你不能停步等候死亡、六月之夜、月光、海滨墓园（节选）、
二十首情诗（节选）、老虎的金黄、典型的夜晚、柏拉特罗与我（节选）、俄罗斯语言、茅屋、秋颂、五月之夜、生命

同一批还同时命中另外两个模板句式（各 40 处）：

- 记忆卡：`抓住《X》中最鲜明的意象，先记画面再记字句。`
- 场景：`在合适的语境里引用《X》，让诗词活起来学习。`

### 判据的自证性（方法论旁注）

这条和我在 #58 里发现的「麻韵判据把目标字装进证据集」是同一类错误：**判据试图证明「这不是模板」，但它的证据集里装的是它自己写的硬编码字符串。**
只要量产脚本把「慢」字去掉，判据立刻失效——而量产脚本确实这么做了。
硬编码字符串做模板检测，本质上是和量产脚本赛跑，且**检测器已经输了**。

### 建议

1. 检测器从「匹配固定字符串」改成「跨篇重复度」：对 `memory[].d` 做去标题占位后的模板化归约，
   出现次数 > N 的句式一律降级为待补——这样生成器再怎么改字都跑不掉。
2. 同时去掉 `expand &&` 限制：模板检测应与层级无关，精读篇同样该诚实标注。
3. 这 40 首若确要保留「精读」身份，需补人工记忆卡与场景；否则应降级为「拓展」，走诚实路径。

### ⑦ `w_zuiyaoyuan` 空译文块（P2，影响面 1/970）

`世界上最遥远的距离` 标为**精读**、`level≠拓展`、两条 `lines[].m` 均为 `""`、且**无 `no_paraphrase` 兜底**。

渲染分支 `index.html:69565`：`(expand && !hasOrig) ? … : (p.no_paraphrase ? rowO : rowOM)`
→ 精读且无 `no_paraphrase` → 走 `rowOM` → 渲染 2 个**空** `<div class="m"></div>`。
`.tr .row .m{margin-top:7px}` → 每句下方多出 7px 无意义空白，且不显示任何「译文补充中」说明。

修法：给该篇补 `"no_paraphrase": true`（走 `rowO`，只显示原文），或补译文。
